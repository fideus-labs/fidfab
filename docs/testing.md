# Tests

| Test | Where it runs | Checks |
|---|---|---|
| `tests/validate-workflows.sh` | host, CI | `fabro validate` on every workflow, each of which ends the run on a failed stage (`on_failure="exit"`) |
| `scripts/sync-components.sh --check` | host, CI | vendored components match `components/` |
| `tests/test-setup.sh` | host, CI | `scripts/setup.sh fabro` runs the scripted `--skip-llm` install when `gh` is logged in, else the wizard; a secret already in the vault is not requested again; the `author` step writes `git config` identity to `[run.git.author]` once; the `github-app` step registers an App only when Fabro has none, or adopts an existing one (its IDs from `gh`, a key and secrets into the vault, then the settings table), adds the dev-token login back next to GitHub sign-in once, and prints its permission and installation pages (stubbed `fabro`/`gh`/`claude`/`codex`) |
| `tests/test-build.sh` | host, CI | `docker/build.sh` passes the host's `claude` / `codex` version to the build as a floor unless the version is set by hand, the Dockerfile quotes the specs that receive it, and a host git URL rewrite reaches the build only when it reads without credentials (stubbed `docker`/`claude`/`codex`) |
| `tests/test-bootstrap.sh` | host, CI | `fidfab-bootstrap` records the plan slug: the `plan_slug` input, or `<date>-<topic branch the run started from>` when it is still `task` |
| `tests/test-review-wrappers.sh` | host, CI | after `fabro fork`, whose fresh sandbox missed bootstrap, `fidfab-codex-acp` writes `auth.json` (mode 600) from `CODEX_AUTH_JSON_B64` unless Codex has one and, signed in, answers `initialize` with no sign-in method, and `fidfab-coderabbit available` logs in again from `CODERABBIT_API_KEY` without touching it; `not_authenticated` without a key is unavailable; `fidfab-coderabbit review` saves the review and fails unless it completed (stubbed `codex-acp`/`coderabbit`) |
| `tests/test-pr-steward.sh` | host, CI | `fidfab-pr-status` lists threads with authors, quotes comment text inert, routes gated runs to the screen, counts failed and pending legacy commit statuses, and records its label as `pr_status` and the head it checked in `pr-head`; `fidfab-pr-reply` posts only screened threads, pushes first, does not repeat posted replies on retry, and its preview flags a push that fails a dry run (stubbed `gh`) |
| `tests/test-logical-commits.sh` | host, CI | every workflow hands over from the PR steward to the history rewrite and to nothing else, and the rewrite leads on (not nowhere, not back to the steward), with node statements wrapped over lines read and any reference or edge the scanner cannot read failing; the rewrite runs only on `context.pr_status=done`; the stage is Claude opus at medium effort with `fidelity="truncate"`, and its prompt keeps the pull-request lookup without forks, the fetch-failure stop, the identical-tree-id checks (against GitHub and against the state before), the clean-work-tree checks with untracked files listed, the rule that GitHub moved only by checkpoints since the recorded commit or holds a recorded attempt (a push, rewording or rewind by someone else stops it), the leased force-push and the `Fabro-Run:` trailer; the agent sits between the `fidfab-history-tree record` and `verify` nodes (a failed record skips it), a failed verify stops at a human gate, and the helper records only when GitHub moved forward from the steward's cleared head along the checkout (a rewind or foreign push before the record fails), passes a code-preserving rewrite and fails changed code in HEAD or on the remote, another branch, and a pushed branch that disappeared; each built-in `workflow.toml` has the blocking `run_complete` hook `fidfab-history-tree trim`, which drops the empty checkpoints after a verified rewrite and leaves alone checkpoints that hold changes, empty commits that are not Fabro's, a commit pushed meanwhile, changed code, a history the rewrite did not touch and the history before the rewrite, also when the rewritten head is an empty checkpoint from it, and fails without changing anything when the commit GitHub had before the rewrite is not in the checkout |
| `tests/test-pipeline-order.sh` | host, CI | `small`, `medium` and `verify` run coverage, the Codex review, the Claude review, the CodeRabbit review, the security review, the personal-data audit, commit and PR, the steward and the history rewrite, in that order, with each stage told by the component it imports and a fork, a loop, an edge from off the chain into a stage after coverage, a stage imported a second time or an edge the scanner cannot read failing; the prompt that addresses a review names the response record of every review before it and of none after it |
| `tests/test-effort-levels.sh` | host | every Claude Code, Codex and Gemini stage sets its effort explicitly, at the level its agent and the one role word in its `class` call for (Claude implementation and planning `xhigh`, Claude and Codex review and security `high`, everything else `medium`; the stages that verify and address the Claude and Codex reviews `xhigh`); the Gemini default in each `workflow.toml` and the Codex config default are `medium` |
| `tests/check-model-aliases.sh` | host, CI (from `validate-workflows.sh`) | every `--model` in a workflow or component `acp.command` names an alias the bare-named `fidfab-*-acp` wrapper resolves; literal model IDs, `--model=` and a `--model` without a value are rejected |
| `tests/test-model-aliases.sh` | host | `check-model-aliases.sh` against scratch repositories with the real wrappers: known aliases pass, removed aliases, unknown wrappers, path-qualified wrappers and malformed `--model` arguments fail, and the repository's own workflows pass |
| `tests/test-codex-model.sh` | host, image (from `test-codex-acp.sh`) | `fidfab-codex-acp` resolves `terra` (also without `--model`), takes `FIDFAB_MODEL_TERRA` over it, rejects `luna`, unknown efforts and IDs that would break the config JSON, and passes `--effort` through; the Codex config defaults to the `terra` model (stubbed `codex-acp`) |
| `tests/test-tools.sh` | image | pixi, rustup/cargo, vite+, claude, codex, coderabbit, serena, ccc, gh, skills present; gh answers github.com credentials under a Fabro stage's empty credential store; the `gh` wrapper takes Fabro's renewed token over the stage's `GITHUB_TOKEN` |
| `tests/test-coderabbit.sh` | image | CLI installed; with `CODERABBIT_API_KEY`, `auth login` and `auth status --agent` succeed |
| `tests/test-claude-acp.sh` | image | ACP `initialize` handshake; with a token, a full `session/prompt` round-trip returns the expected marker |
| `tests/test-codex-acp.sh` | image | Same for Codex |
| `tests/test-image.sh` | host | Runs the image tests in `docker run`, passing credentials through |

`tests/acp-smoke.mjs` is a dependency-free ACP client (JSON-RPC over stdio) used by both ACP
tests; it follows the protocol's `initialize` → `session/new` → `session/prompt` sequence
([ACP schema](https://agentclientprotocol.com/protocol/schema)).

GitHub Actions (`.github/workflows/ci.yml`) runs validation, shellcheck, hadolint, and the
Node syntax check on every push and PR; the image build and tool tests run on manual dispatch.
